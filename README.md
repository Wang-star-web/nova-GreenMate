# GreenMate — 番茄大棚环境监测课程项目 (B01 / B02 / B03 / B04 / B05 / B06 / B07 / B08)

番茄大棚环境监测课程项目,当前包含 B01(智能交互模块)、B02(环境解析与证据提取模块)、
B03(规则判断模块)、B04(机器学习异常检测模块)、B05(证据融合与可信降级模块)、
B06(多视图报告生成模块)、B07(主程序组装模块)与 B08(整体交付验证脚本):

- **B01** 命令行交互入口:采集 4 项环境参数并校验合法性,每次采集自动生成唯一 `run_id`,
  原始数据保存至 `evidence/raw/{run_id}.json`;只负责交互输入与原始数据保存。
- **B02** 指标解析模块:读取 B01 的原始数据,对四项指标逐项判定 偏低/适宜/偏高,
  判定依据与原始数值写入 `evidence/parsed/{run_id}_parsed.json`;只做指标解析,不做综合结论。
- **B03** 规则判断模块:加载专家规则库 `b03_rules.json`,基于 B02 的判定结果综合判断
  正常/需要预警,记录本次用到的规则写入 `evidence/rule/{run_id}_rule.json`;
  只做规则推理,不调用机器学习。
- **B04** 机器学习异常检测模块:基于孤立森林(IsolationForest)读取历史原始数据训练模型
  (random_state 固定可复现),预测指定 run_id 输出是否异常与异常得分,结果写入
  `evidence/ml/{run_id}_ml.json`;独立运行,不依赖 B02/B03。
- **B05** 证据融合与可信降级模块:融合 B03 与 B04 两路证据生成最终评估结论,
  核心要求可信降级——证据不一致降级、证据缺失标注【证据缺失】不硬补,
  结果写入 `evidence/final/{run_id}_final.json`。
- **B06** 多视图报告生成模块:读取 final 结论渲染自包含 HTML 报告(①原始数据
  ②指标解析 ③规则与机器学习证据 ④综合结论 四个标签页视图),保存到
  `report/{run_id}_report.html`;零外部依赖,离线双击即开。
- **B07** 主程序组装模块:统一入口,把 B01~B06 串联成完整流水线
  (采集 → 存储 → 解析 → 规则 → ML → 融合 → 报告),全程使用同一个 run_id,
  任一阶段失败按降级策略继续。
- **B08** 整体交付验证脚本:输入 run_id 校验全部交付产物(raw/parsed/rule/ml/final
  证据 + HTML 报告)的存在性与内容有效性,输出三态校验清单(OK/缺失/异常)与
  确定性结果指纹,重复运行指纹一致即可确认结果可复现。

## 运行方式

```bash
py b01_cli.py
```

主菜单:

| 选项 | 功能 |
|---|---|
| ① | 新建一组采集数据 |
| ② | 查看历史 run_id 列表 |
| ③ | 退出程序 |

交互说明:

- 采集过程中输入 `q` 可取消本次采集(不保存任何数据);
- 空输入、非数字、超出范围等非法输入均给出针对性中文提示并要求重新输入,程序不会崩溃;
- 按 `Ctrl+C` 或输入流结束(EOF)时程序安全退出,无异常堆栈。

## B01 补全(Web 展示 / LLM 问答 / A-B 验证 / 失败验证)

B01 在采集功能之外补全了以下能力(全部并入 `b01_cli.py`,B02~B08 未改动):

| 子命令 | 功能 |
|---|---|
| `py b01_cli.py` | 采集主菜单(原始功能,不变) |
| `py b01_cli.py web` | 启动本地 Web 页面(127.0.0.1:8123):环境状态 A/B 切换、环境数据展示(每项指标标记 `source_type=SIMULATED`)、固定提问"当前环境怎么样?"、LLM 实时回答、新建采集(手动输入 4 项参数,服务端按 CLI 同规则校验后保存到 `evidence/raw/`)、历史采集结果列表(最近 50 条) |
| `py b01_cli.py abtest` | 自动 A/B 验证:两套环境状态(状态 A 适宜 / 状态 B 异常)、只切换状态、固定提问;LLM 两次回答内容不同即 PASS,相同即 FAIL;失败路径如实上报 |

**环境数据展示**:采集的 raw 记录顶层新增 `"source_type": "SIMULATED"` 字段;Web 页面每张指标卡均显示 `source_type=SIMULATED` 徽章;发给 LLM 的提示词同样注明数据为模拟采集。

**LLM 调用**(DeepSeek OpenAI 兼容接口,全部可用环境变量覆盖):

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `B01_LLM_BASE_URL` | `https://api.deepseek.com/chat/completions` | 接口地址 |
| `B01_LLM_MODEL` | `deepseek-chat` | 模型名 |
| `B01_LLM_TIMEOUT` | `30`(秒) | 连接与读取超时 |
| `B01_WEB_PORT` | `8123` | Web 页面端口 |

API Key 读取顺序:`DEEPSEEK_API_KEY` → `ANTHROPIC_AUTH_TOKEN`(均从环境变量读取,代码中零硬编码)。

**Web 新建采集与历史记录**:网页端可手动输入 4 项环境参数,服务端按与 CLI 完全一致的
合法范围逐字段校验(错误文案逐条对齐),成功后复用 `gen_run_id`/`save_record` 生成
`run_id` 并保存到 `evidence/raw/{run_id}.json`(结构与 CLI 采集完全同构);历史面板
读取 `evidence/raw` 展示最近 50 条记录。历史读取容忍早期记录缺少 `source_type` 字段
与损坏文件(跳过并计数),全部文本以 `textContent` 渲染,防 XSS。

**降级提示横幅**:页面加载时未配置 API Key,或提问失败(密钥无效/网络超时等)时,
页面顶部展示降级提示横幅,并明确说明"本地新建采集与历史查看功能不受影响";
`/api/state` 与 `/api/switch` 响应仅返回 `llm.key_configured` 布尔标记,绝不返回密钥。

**失败验证(禁止伪造静态成功结果)**:成功路径只有一条——解析真实 API 返回的内容。
API Key 错误(HTTP 401/403)、网络超时/连接失败、返回内容无法解析等一律在
**页面错误框与 `logs/b01_llm.log` 日志**中明确输出失败(`error_type` + 中文说明),
绝不返回伪造的成功答案。注意:`/api/ask` 恒返回 HTTP 200,内层 JSON 的
`status` 字段才是成败信号(页面据此渲染成功/失败框)。

**日志**:`logs/b01_llm.log`(自动创建,UTF-8 追加):每次提问记录 `[请求]`(状态/问句/
环境值/Key 来源名,绝不记录 Key 值)、`[成功]`(回答)或 `[失败]`(error_type+message)、
状态切换记录 `[切换]`。

## B02 指标解析模块

运行方式(二选一):

```bash
py b02_parse.py run_20261022_220400_485a96   # 直接解析指定 run_id(可带 .json 后缀)
py b02_parse.py                              # 不带参数:列出可用 run_id 交互选择
```

判定阈值(农学常规带,边界值含在适宜区间内):

| 指标 | 单位 | 偏低 | 适宜 | 偏高 |
|---|---|---|---|---|
| 温度 | ℃ | < 15 | 15 ~ 30 | > 30 |
| 湿度 | %RH | < 45 | 45 ~ 85 | > 85 |
| CO₂浓度 | ppm | < 800 | 800 ~ 1500 | > 1500 |
| 光照 | lux | < 10000 | 10000 ~ 70000 | > 70000 |

输出:`evidence/parsed/{run_id}_parsed.json`(目录不存在时自动创建),包含每项指标的
原始数值 `value`、判定结果 `verdict`、判定依据 `basis` 及本次采用的判定规则 `rules`,
证据文件自带判定证明。非法输入(文件缺失、JSON 损坏、字段缺失、数值非法等)均给出
中文提示并安全退出,程序不会崩溃。

## B03 规则判断模块

运行方式(二选一):

```bash
py b03_rule.py run_20261022_220400_485a96   # 直接判定指定 run_id
py b03_rule.py                              # 不带参数:列出可判定数据交互选择
```

专家规则库 `b03_rules.json`(8 条原子规则,任一触发即判"需要预警",全部未触发判"正常"):

| 规则 | 规则名 | 触发条件 | 建议措施 |
|---|---|---|---|
| R1 | 高温预警 | 温度偏高(> 30 ℃) | 通风或湿帘降温 |
| R2 | 低温预警 | 温度偏低(< 15 ℃) | 关闭通风口并加温 |
| R3 | 高湿病害风险 | 湿度偏高(> 85 %RH) | 通风排湿、控制浇水 |
| R4 | 低湿授粉不良 | 湿度偏低(< 45 %RH) | 喷雾增湿 |
| R5 | CO₂不足光合受限 | CO₂偏低(< 800 ppm) | 通风或 CO₂ 增施 |
| R6 | CO₂偏高需通风 | CO₂偏高(> 1500 ppm) | 打开通风口换气 |
| R7 | 光照不足 | 光照偏低(< 10000 lux) | 清洁棚膜或补光 |
| R8 | 强光灼伤风险 | 光照偏高(> 70000 lux) | 遮阳网或遮光剂 |

输出:`evidence/rule/{run_id}_rule.json`(目录不存在时自动创建),含 8 条规则的逐条匹配
情况 `rule_results`(含实测值、匹配与否、规则说明与建议)、实际触发的规则
`triggered_rules`、结论 `conclusion`(正常/需要预警)与判定依据 `conclusion_basis`,
完整记录本次判断用到的规则。非法输入(规则库缺失/损坏、解析文件缺失/结构异常等)
均给出中文提示并安全退出,程序不会崩溃。

## B04 机器学习异常检测模块

依赖安装(若未安装):

```bash
py -m pip install scikit-learn
```

运行方式(二选一):

```bash
py b04_ml.py run_20261022_220400_485a96   # 直接预测指定 run_id
py b04_ml.py                              # 不带参数:列出可用原始数据交互选择
```

模型:`IsolationForest(n_estimators=100, contamination=0.05, random_state=42, max_samples="auto")`,
`random_state` 固定保证结果完全可复现。训练集 = `evidence/raw` 全部历史数据中
**排除目标 run_id 自身**的有效文件(至少需要 2 份),坏文件自动跳过并记录在
`skipped_files`。异常得分 = `-decision_function`,越大越异常,阈值 0;
是否异常直接取 `predict()` 结果。

输出:`evidence/ml/{run_id}_ml.json`(目录不存在时自动创建),含模型参数、训练文件
清单 `training_files`、特征值 `features`、`is_anomaly`、`anomaly_score` 与判定依据
`basis`,证据文件自带本次预测的全部信息。

> **注意:模型对样本量敏感。** 历史数据不足约 15 组时,孤立森林难以稳定区分异常
> 样本(得分可能全部为 0、全部判正常)。建议先用 B01 多采集几组环境数据再使用本模块。

## B05 证据融合与可信降级模块

运行方式(二选一):

```bash
py b05_fusion.py run_20261022_220400_485a96   # 直接融合指定 run_id
py b05_fusion.py                              # 不带参数:列出可融合数据交互选择
```

融合策略(规则优先,机器学习证据作为佐证影响可信度):

| B03 规则 | B04 ML | 最终结论 | 可信度 |
|---|---|---|---|
| 正常 | 正常 | 正常 | 高 |
| 正常 | 异常 | 正常(ML检测到偏离历史分布,建议人工关注) | 中 |
| 需要预警 | 正常 | 需要预警(ML未检出异常) | 中 |
| 需要预警 | 异常 | 需要预警(两路一致确认) | 高 |
| 缺失 | 有 | 【证据缺失】结论仅基于机器学习证据 | 低 |
| 有 | 缺失 | 【证据缺失】结论仅基于规则证据 | 低 |
| 缺失 | 缺失 | 【证据缺失】无法融合判定 | 低 |

**可信降级**:两路一致 → 高;不一致 → 中;任一缺失 → 低并在结论与依据中明确标注
`【证据缺失】`,**不硬补结果**。证据文件存在但内容无效(坏 JSON、字段缺失等)按缺失处理。

输出:`evidence/final/{run_id}_final.json`(目录不存在时自动创建),含两路证据投影
(`rule_result`/`ml_result`,缺失一侧为 `null`)、`final_conclusion`、`trust_level`、
`degraded_reasons` 与融合依据 `basis`,证据文件自带本次融合的全部信息。

## B06 多视图报告生成模块

运行方式(二选一):

```bash
py b06_report.py run_20261022_220400_485a96   # 直接生成指定 run_id 的报告
py b06_report.py                              # 不带参数:列出可生成报告的 run_id 交互选择
```

输入:必需 `evidence/final/{run_id}_final.json`(缺失会提示先运行 B05);
`evidence/raw`、`evidence/parsed`、`evidence/rule`、`evidence/ml` 子证据按 B05 的
`evidence_status` 权威口径加载,缺失时在对应视图内以【证据缺失】占位块提示,不硬补数据。

报告包含四个标签页视图(顶部按钮切换,内联 JS,无任何外部依赖):

| 视图 | 内容 |
|---|---|
| ① 原始数据 | 4 张数值卡片 + 数值在 B01 合法采集范围内的位置条 |
| ② 指标解析 | 判定表(指标/数值/判定标签/判定依据)+ 数值在适宜区间内的位置条 |
| ③ 规则与机器学习证据 | B03 规则面板(结论、触发规则、8 条规则逐条匹配表)+ B04 机器学习面板(结论、异常得分条、模型参数、训练集、特征值) |
| ④ 综合结论 | 最终结论横幅 + 可信度星级 + 两路证据完整性 + 可信降级原因 + 融合依据 |

输出:`report/{run_id}_report.html`(目录不存在时自动创建),UTF-8、自包含
(内联 CSS 明暗双主题 + 内联 JS 标签页切换,无 CDN、无图片),离线双击即开。

## B07 主程序(统一入口流水线)

运行方式:

```bash
py b07_main.py              # 完整流水线:交互采集后自动执行 B02~B06
py b07_main.py run_xxx      # 对已有 run_id 从解析阶段开始重跑(跳过采集,幂等覆盖)
py b07_main.py --help       # 查看用法说明
```

流水线六个阶段(全程使用同一个 run_id):

| 阶段 | 内容 | 模块 | 产物 |
|---|---|---|---|
| 1/6 | 采集输入 | B01 | `evidence/raw/{run_id}.json` |
| 2/6 | 解析提取证据 | B02 | `evidence/parsed/{run_id}_parsed.json` |
| 3/6 | 专家规则判断 | B03 | `evidence/rule/{run_id}_rule.json` |
| 4/6 | ML 异常检测 | B04 | `evidence/ml/{run_id}_ml.json` |
| 5/6 | 证据融合可信降级 | B05 | `evidence/final/{run_id}_final.json` |
| 6/6 | 生成 HTML 报告 | B06 | `report/{run_id}_report.html` |

**降级继续策略**:阶段 2~6 任一失败(如首次运行历史数据不足导致 ML 无法训练、
规则库缺失)打印警告并继续——B05 自动把缺失证据标注【证据缺失】并降级可信度,
B06 在对应视图渲染占位,整条流水线仍完整走通并产出报告;阶段 1 取消或保存失败则终止。

注意:启动时会导入 scikit-learn,首次运行有 1~2 秒启动耗时,属正常现象。

## B08 整体交付验证脚本

运行方式:

```bash
py b08_verify.py run_20261022_220400_485a96   # 直接校验指定 run_id
py b08_verify.py                              # 不带参数:列出可校验的 run_id 交互选择
```

校验内容:对指定 run_id 逐一检查 6 个交付产物 —— `evidence/raw/{run_id}.json`、
`evidence/parsed/{run_id}_parsed.json`、`evidence/rule/{run_id}_rule.json`、
`evidence/ml/{run_id}_ml.json`、`evidence/final/{run_id}_final.json`、
`report/{run_id}_report.html`,输出三态清单:

| 状态 | 含义 |
|---|---|
| ✓ OK | 文件存在且内容有效(JSON 可解析且 run_id 字段一致;HTML 非空) |
| ✗ 缺失 | 文件不存在 |
| ⚠ 异常 | 文件存在但内容无效(JSON 损坏 / run_id 不一致 / HTML 为空) |

每个文件附带 SHA-256 内容摘要,并汇总出确定性「结果指纹」(不含校验时间):
**重复运行同一 run_id,结果指纹一致即确认结果可复现、证据未被改动**。

模块链路:B01 采集 → B02 逐项判定 → B03 规则综合判定 / B04 独立检测;
B05 融合 B03+B04 两路证据输出最终评估;B06 基于最终结论渲染多视图报告;
B07 提供统一入口,一条命令跑完 采集→解析→规则→ML→融合→报告 全流程;
B08 校验整套交付产物的完整性,结果指纹保证可复现。
