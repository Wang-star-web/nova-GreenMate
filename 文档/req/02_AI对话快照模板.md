# AI 对话快照 · 采集与整理模板

**用途：** 章程要求「AI 对话历史快照 —— 至少 3 个核心功能迭代的完整 Prompt 链」
**制定日期：** 2026-10-25

> ### ⏳ 什么时候看这份：**下次打开编程 AI 之前**
>
> 不用通读。现在只需要看两节：
> - **第七节**（截图技术规范）：先把分辨率、浅色主题、遮密钥定下来
> - **第三节**（五个文件逐个说明）：知道要截哪几张，边做边截
>
> 剩下的（目录怎么排、`说明.md` 怎么写、对话丢了怎么办）等交稿前再查。
>
> **核心只有一句：截图必须当场截。** 事后回忆写出来的不是对话，是复述。

---

## 一、这份材料为什么最容易失分

因为大多数人交上来的不是"过程"，是"结果"。

| 错误做法 | 为什么不算 |
| --- | --- |
| 只截最终页面效果 | 那是验收证据，不是过程证据。任何作品都有最终效果 |
| 把对话整理成段落文字 | 那是你的复述。评委会当回忆录看 |
| 只截 AI 的回答，不截自己的提问 | 意图控制考察的是**你怎么问**，不是 AI 怎么答 |
| 一次就成功的对话 | 看不出纠偏能力。这类案例写不出分 |
| 一张超长拼图 | A4 打印后全是糊的，等于没交 |

**合格的样子**：评委看 2 分钟，能说出"他第一次要的是 X，AI 给了 Y，Y 在某种情况下不行，他改成 Z 之后好了"。

## 二、目录结构（每个案例一套）

```text
02_AI对话快照/
├── 索引.md
├── 01_<案例名>/
│   ├── 说明.md
│   ├── 对话记录.md        ← 工具能导出时放这里（优于截图）
│   ├── 01-我的原始提问.png
│   ├── 02-AI第一次的方案.png
│   ├── 03-我发现的问题.md
│   ├── 04-我的纠偏指令.png
│   └── 05-验证结果.png
├── 02_<案例名>/
└── 03_<案例名>/
```

案例名用「功能 + 遇到的问题」，例如：
- `01_知识库回答编造资料`
- `02_工具调用缺参数`
- `03_外部服务超时导致白屏`

**不要**用 `案例1` `案例2`。名字本身就说明你当时在解决什么。

## 三、五个文件逐个说明

### `01-我的原始提问.png`

**截什么：** 你第一次提要求的那条消息，完整，含上下文。

**必须能看到：**
- 你的完整提问（不是"帮我优化一下"这种，要有具体任务）
- 时间戳（侧边栏或消息时间都行）

**不行的：** 只截半个气泡；裁掉了后面的约束条件；用文字重打一遍。

---

### `02-AI第一次的方案.png`

**截什么：** AI 给你的第一版答复，或者第一版代码。

**必须能看到：**
- AI 实际给的内容（代码、方案、输出）
- 如果内容太长，**分段截，编号连续**（`02a`、`02b`），不要拼成一张长图

**为什么这一张最重要：** 没有"第一版的问题"，后面的纠偏就没有对象。**这一张缺失，整个案例作废。**

---

### `03-我发现的问题.md`

**这一份不是截图，是文字，100–200 字。**

模板：

```markdown
## 我发现的问题

**怎么发现的：** <你做了什么测试 / 输入了什么数据>

**具体现象：** <看到了什么，用输入和输出说话>
- 输入：<具体输入>
- 期望：<应该是什么>
- 实际：<实际是什么>

**为什么不能接受：** <这个错误在真实使用中会导致什么后果>

**我当时判断的原因：** <你觉得问题出在哪，一句话>
```

**示例（虚构，仅示范结构）：**

> **怎么发现的：** 用一份没有该字段的数据测试导出功能。
> **具体现象：** 输入时间为 `2026-10-25 08:00`，期望导出为 `08:00`，实际导出 `00:00`。
> **为什么不能接受：** 所有跨时区用户的报表时间都会偏 8 小时，属于数据错误而非显示问题。
> **我当时判断的原因：** 导出环节重新做了时间格式化，没沿用读取时已经转换过的本地时间。

> **这一份是整套材料里最值钱的。** 评委判断一个学生"有没有工程判断力"，看的就是这里：他能不能用输入输出把问题说清楚，而不是"感觉不太对"。

---

### `04-我的纠偏指令.png`

**截什么：** 你指出问题、要求修改的那条消息，以及 AI 修改后的回复。

**必须能看到：**
- 你怎么描述这个问题（是指出错误？给反例？加约束？）
- 你给的新要求（**和第一次的差别在哪**）
- AI 改完的结果

**如果一轮没改对：** 继续截，编 `04b` `04c`。**两三轮才改对，比一次改对更能说明控制力。**

---

### `05-验证结果.png`

**截什么：** 改完之后重新跑的结果。

**必须能看到：**
- 同样的输入，这次输出对了
- 最好有对照（改前 / 改后 并排）

**不要：** 用"应该可以了"当验收。验收必须有输出。

## 四、`说明.md` 模板（每个案例一份，控制在 1 页）

```markdown
# <案例名>

**时间：** <YYYY-MM-DD>
**涉及模块：** <文件名或功能模块>
**对应提交：** `<commit hash>`
**对应技术文档：** <3.2 / 3.3 / 3.4>

## 一句话结论

<这个案例证明了什么能力。例如："证明了我在让 AI 写检索逻辑时，能用反例约束它不要编造资料出处。">

## 过程概要

| 阶段 | 我做了什么 |
| --- | --- |
| 提要求 | <一句话> |
| 检查 | <我用什么方法验证 AI 给的对不对> |
| 发现问题 | <一句话> |
| 纠偏 | <我改了哪一句指令 / 加了什么约束> |
| 结果 | <一句话 + 数字或现象> |

## 我从这件事上学到什么

<2-3 行。这一节不是凑字数，是证明你不是被动接受 AI 输出。>
```

> **最后那一节不要省。** 它和技术文档的灵魂是同一个：你在控制 AI，还是在被它带着走。

## 五、`索引.md` 模板（放在 02 目录根下）

```markdown
# AI 对话快照索引

共 3 个案例，覆盖 <功能A>、<功能B>、<功能C> 三个核心迭代。

| 编号 | 案例 | 解决的问题 | 对应提交 | 截图数 |
| --- | --- | --- | --- | --- |
| 01 | <案例名> | <一句话> | `<hash>` | 5 |
| 02 | <案例名> | <一句话> | `<hash>` | 6 |
| 03 | <案例名> | <一句话> | `<hash>` | 5 |

## 采集说明

- 对话工具：<Cursor / Claude Code / ...>
- 截图时间：<原始对话当场截图 / 于 X 月 X 日从会话历史导出>
- 是否有缺失：<无 / 案例 3 的 04 步骤未当场截图，已于 X 月 X 日补做一次同样的改动并留痕>
```

**"是否有缺失"这一行必须写。** 主动说明缺失的和被评委发现的，性质完全不同。

## 六、三种"对话已经丢了"的情况，各自怎么办

### 情况 A：部分案例的对话还在

按上面的结构整理。缺的那部分，在 `说明.md` 里注明"该步骤的原始对话未保留，以下为当时提交记录的对照"。

### 情况 B：全部对话都没了，但代码和提交记录在

不要伪造。改用**替代证据链**，写进 `索引.md`：

```markdown
## 采集说明

本项目开发过程中未系统保留对话记录。以下为可交叉验证的替代证据：

1. Commit 记录及其变更内容（`01_Git提交日志/`）
2. 仓库源码中带日期与原因的约束注释（写明文件名和行号，评委可现场核对）
3. 报错原文与修复后的日志对比（放在 `02_AI对话快照/补充证据/`）

三者时间线一致。案例说明中的"我的要求"部分，依据提交内容与注释还原，非原始对话原文。
```

这样拿不到满分案例分，但**不会因为造假被判零分**，而且"如实说明"本身是加分项。

### 情况 C：还有时间重做（截止前 ≥ 15 天）

**这是最好的情况，别浪费。**

挑 2–3 个现在真的要改的地方（不是硬造的假任务），完整走一遍并留痕：
1. 提要求时就把话说明白（写清输入、输出、边界）
2. 拿到 AI 方案后**真的去测**，用真实数据
3. 找出问题，截下 AI 第一次错的样子
4. 纠偏，截下你改的那句话
5. 验证，截下结果
6. 提交，写清 commit

**真实发生在本周的过程，好过伪造在过去的过程。** 而且这条路径做出来的案例质量更高——因为你是带着"这次要留痕"的意识在做，问的问题本身就更专业。

## 七、截图技术规范（照这个做，省一半返工）

| 项 | 要求 |
| --- | --- |
| 分辨率 | 截图宽度 ≥ 1200 px。太窄在 A4 上看不清 |
| 格式 | PNG（文字更清晰），不要 JPG |
| 标注 | 要看的那一行加红框或箭头，**一张图只标一处** |
| 裁切 | 只裁掉与内容无关的区域（如侧边栏其他会话名），不要裁到正文 |
| 拼接 | 禁止。多屏就多张，编号连续 |
| 遮挡 | 密钥、token、个人手机号必须打码，**但不要把整段提问也打掉** |
| 来源 | 必须是屏幕截图，禁止手机拍屏幕 |

**一个常见错误：** 用深色主题截图。打印出来一片黑，评委看不清。**在 A4 上，浅色主题的可读性远高于深色。**

### 优先级：导出记录 > 截图 > 文字复述

先看你的工具能不能导出整段会话，能导出就别截图：

| 工具 | 导出方式 |
| --- | --- |
| Claude Code | `/export`，或会话记录文件（一般在 `~/.claude/` 下） |
| Cursor | 会话历史里可复制整段，存成 `.md` |
| 网页版类工具 | 右上角"分享 / 导出"，部分版本需要手动全选复制 |

**导出的 `.md` / `.txt` 比十几张截图强**：全文可搜索、评委不用放大、也不会漏掉某一句。只在"导出会丢信息"时才截图——比如要看界面上的按钮、报错弹窗、渲染结果。

两种都留是最好的：导出的全文放 `02_AI对话快照/<案例名>/对话记录.md`，关键几屏再截 4 张图。
